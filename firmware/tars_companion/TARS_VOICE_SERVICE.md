# TARS 0.16.4 语音版

本版由 ESP32 固件和 Windows Companion 共同运行。电脑需开机、登录 Windows、与机器人处于可互通的局域网，云端对话还需互联网。无需 DeepSeek API。

## 日常使用

- Windows 登录后可自动启动 Companion，无需点击录音或反复粘贴 API Key。
- 待机时音频只在电脑本地进行关键词检测；说 `TARS`、`Hello TARS` 或“塔斯”唤醒。
- 唤醒后直接连续聊天；每次回复和动作结束后重新开始计算 180 秒。静默超过 180 秒回到唤醒待机。
- “结束对话”“停止聊天”“晚安塔斯”“goodbye TARS”“stop listening”结束当前对话，服务继续待机。
- 普通回复跟随用户当前语言。使用已有 TARS 复刻音色 `S_vXjewQyk2`，云模型 `1.2.6.1`。
- 播放和执行动作期间不采集用户声音，不能语音打断；说完后自动恢复监听。此项按用户确认不在本版实现。
- 单句最长约 18 秒，过长输入会停止而不执行不完整动作；长说明请分段说。

## 动作

唤醒后可直接说“向前走一步”“左转”“右转”“打个招呼”“开心一下”“表示感谢”等。每个用户发言最多一个动作；三个步态每次支持 1～3 次。

流程：识别当前指令 → 本地严格映射固定动作 → 语音表达即将执行 → 确认播放结束并释放音频 → 查询状态 → Arm → motion.execute → 等待终态 → Disarm → 恢复监听。预告不是完成证明，日志和屏幕以固件终态为准。

语音开放 3 个步态和 21 个日常动作。support_probe 和 hello_small 是准备测试入口，不开放给语音。需要支撑的动作仅在本地部署确认后开放；此台机器的支撑条件已由用户确认。否定句、引用或历史记忆不能执行动作。后退、横向平移、任意舵机角度均不支持。

连接恢复会保持输出关闭，重新要求唤醒和全新的语音命令，不续跑旧动作。动作结果不确定时不重试该动作。

## 记忆

`data/tars-voice.sqlite3` 保存带时间的对话、明确要求记住的事实、每日对话摘录索引和真实动作结果。下次启动继续使用同一个数据库。

每次云会话带入近期记录、事实和索引；模型通过 memory_lookup 按关键词或日期检索更早的内容。每日索引是原文摘录，不是额外大模型编造的摘要。数据库保留历史，但受上下文长度限制，不能保证每次把所有历史同时交给模型。

可说“记住：我的基地叫晨星”或“remember that my base is called Morning Star”；可说“忘记：晨星”删除匹配的本地记录与派生索引。删除本地记忆不代表删除服务商日志。程序不永久保存日常麦克风录音。

## 本机入口

- `Start-Tars.cmd`：手动启动/诊断窗口。
- `Start-Tars.ps1 -Unattended`：后台启动，复用已保存配置。
- `Install-Autostart.ps1`：为当前 Windows 用户安装登录启动快捷方式。
- `Stop-Tars.cmd`：请求后台停止并关闭运动输出；前台模式还支持 `/stop`、`/disarm`、`/quit`。
- `Start-Tars.ps1 -Setup`：重新确认配置。

API Key 保存在 `doubao-key.credential.local.xml`，使用当前 Windows 账户加密；不写入固件。配对文件为 `wifi-audio.local.json`。这两个文件及实际记忆不随公开交付包分发。

## 免费额度边界

当前免费额度由用户从控制台确认。`data/free-allowance.sqlite3` 持久化本地使用估计，每轮预留 20,000 Token，取得用量后结算；异常或崩溃不自动退回预留。另保留 50,000 Token 缓冲。重启不能重置这份账本。

这是本地保守估计，不是火山账单系统的硬限额，也无法看到其他程序同时消耗的额度。额度不足或用量缺失时停止，不能承诺云端永远绝无扣费。程序不购买套餐、不启用付费资源。确认控制台新余额后可用 `-Setup -RenewFreeSnapshot` 更新快照。

## 固件差异

以 0.16.3-motionpack 完整源码为基础，运动组件保持逐文件相同。语音固件支持持续本地唤醒、音频故障诊断和设备端 PSRAM 缓存播放。2 秒认证心跳失联保护、单段播放 12 秒上限、音频运动互斥保持不变。一次最多缓存 8 秒的 PCM，传输完成才启动播放；完成确认在功放停止后返回，运动随后才可以开始。

新增 TWA1 音频类型 23/24/25（BUFFER_START/BUFFER_PCM/BUFFER_COMMIT）。START 包含 1 字节音量和 4 字节网络序长度；PCM 每包不超过 512 字节；COMMIT 的 ACK 在实际播放结束后发出。播放由独立任务执行，网络任务仍处理心跳和停止指令。hello 包中的 buffered_audio_v1=true 用于防止 Companion 对旧固件误用新协议。

持续收音每 32ms 合并发送一次麦克风 PCM，采集期间仍每个 I2S 小块检查控制输入。电脑端音频心跳和控制租约按固定周期发送，不再把 ACK 等待时间累加到心跳间隔；最多四条心跳在途，超时仍关闭连接。断线日志记录最大 ACK 延迟、接收间隔和心跳调度延迟，不记录密钥或原始录音。断线清理失败不能阻止进入重连流程。

实际更新仅写应用区 0x10000，原分区表、NVS、Wi-Fi 配对和机械标定保留。已用 Flash 区域的升级前备份仅保存在本机 evidence/voice-install，不进入分发包。
